# Findings and severity

Severity is stable by code, independent of the exit-state precedence. `critical` concerns invalid or duplicate credit evidence; `high` concerns financial identity/attribute disagreement; `medium` concerns policy or accounting investigation. Inconclusive absence/provider errors are low/info. Verification state distinguishes an observed discrepancy from an unresolved question. Any unresolved/incomplete finding makes the run exit 3 even if below the selected severity threshold.

Every finding supplies its entry/event references where evidence exists, expected/observed values, snapshot identity and recommended investigation. The examples below illustrate detection conditions; none authorizes an automatic correction.

| Code                            | Severity | Meaning, condition and example                                                                                                                     | Investigation                                                                      |
| ------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| WRONG_CHAIN_ID                  | high     | Ledger chain differs from configured chain, e.g. 1 vs 31337. RPC network mismatch instead aborts preflight with exit 2.                            | Verify ledger network identity and configured endpoint.                            |
| WRONG_TOKEN_CONTRACT            | high     | Ledger token differs from configured asset, or the requested receipt event is emitted by another contract.                                         | Compare contract addresses, not symbols.                                           |
| TRANSACTION_REVERTED            | critical | Canonical receipt has failure status; a credited transaction reverted.                                                                             | Inspect execution failure and the application's credit decision.                   |
| TRANSACTION_NOT_OBSERVED        | low      | Credited transaction is not returned by provider, or credit lacks transaction identity. No claim of failure or fraud.                              | Check another trusted node and original credit records.                            |
| TRANSFER_EVENT_NOT_FOUND        | high     | Successful receipt has no requested configured-token event, or only an excluded mint is selected.                                                  | Inspect receipt logs, index and eligibility policy.                                |
| NONCANONICAL_BLOCK              | critical | Receipt block hash differs from canonical header at its height.                                                                                    | Investigate chain view/reorg and affected credits; do not accept receipt alone.    |
| RECORDED_BLOCK_MISMATCH         | high     | Ledger-supplied block hash differs from observed canonical inclusion.                                                                              | Compare historical application evidence with current inclusion.                    |
| REORG_OBSERVED                  | critical | Prior stored canonical event block hash differs from the current canonical hash at that height.                                                    | Trace stored/current headers and all affected credits.                             |
| AMOUNT_MISMATCH                 | high     | Exact decimal base-unit values differ, e.g. credited 100 vs emitted 90.                                                                            | Inspect event value and ledger amount conversion.                                  |
| RECIPIENT_MISMATCH              | high     | Observed recipient differs from ledger deposit address.                                                                                            | Trace the actual recipient and deposit-routing records.                            |
| ACCOUNT_ATTRIBUTION_MISMATCH    | high     | Claimed account does not own the ledger/observed recipient in the independent registry.                                                            | Verify customer address authority independently.                                   |
| DUPLICATE_CREDIT                | critical | Multiple credited entries select the same event identity.                                                                                          | Investigate credit idempotency and distinct log indices.                           |
| AMBIGUOUS_TRANSFER_MATCH        | medium   | Missing log index leaves several possible receipt events.                                                                                          | Recover the exact block-global log index from source evidence.                     |
| UNRECORDED_ONCHAIN_TRANSFER     | medium   | Eligible in-range inbound event has no valid matched ledger association.                                                                           | Determine whether unsolicited transfer or missed/misattributed credit.             |
| ELIGIBLE_DEPOSIT_NOT_CREDITED   | medium   | Uniquely identified eligible event has an entry still marked expected.                                                                             | Inspect application credit processing and eligibility decisions.                   |
| EXPECTED_DEPOSIT_NOT_OBSERVED   | info     | Expected entry has no transaction identity/receipt; attribute candidates may be included. Unresolved, never alleged failed.                        | Recover transaction identity or wait/recheck a trusted provider.                   |
| INSUFFICIENT_CONFIRMATIONS      | medium   | Verified canonical inclusion is below policy at reference head. For credited entries this is a discrepancy; for expected entries an investigation. | Wait for policy eligibility; review credit handling.                               |
| PREMATURE_CREDIT                | medium   | Ledger-supplied credit height implies fewer confirmations than policy, including credit before inclusion.                                          | Verify application's recorded historical timing; distinguish it from RPC evidence. |
| CREDIT_HEIGHT_INCONSISTENT      | medium   | Ledger credit height precedes inclusion or lies after reference head. Future heights are unresolved.                                               | Verify height source, network and historical block assignment.                     |
| HISTORICAL_CONFIRMATION_UNKNOWN | info     | Credited entry lacks credited_at_block. Current eligibility may still verify.                                                                      | Obtain historical application timing if required for the audit.                    |
| RPC_EVIDENCE_UNAVAILABLE        | low      | Timeout/provider/header failure, receipt beyond snapshot, changed anchors, or unavailable historical block. Never absence-as-proof.                | Retry bounded audit with reliable historical RPC data.                             |
| SCAN_INCOMPLETE                 | low      | A discovery chunk fails, exceeds bounds or contains events without matching canonical receipt evidence.                                            | Resolve failed ranges; do not claim full reverse coverage.                         |
| MALFORMED_EVENT_DATA            | high     | Transfer topics/padding/data or receipt-log metadata is malformed or inconsistent.                                                                 | Inspect raw node data and contract compliance; repeat against a trusted node.      |

Selected matching events are referenced by `chain_id:tx_hash:log_index`. A missing receipt has no invented event reference. Initial configuration/network/head errors are safe execution errors, not findings in a fabricated audit. Human-readable JSON/text output and exit thresholds use the same code/severity registry in `internal/domain`.
